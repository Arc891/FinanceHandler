# Fix: Discord Bot Heartbeat Blocking - Async Conversion - 2025-12-17

## Problem

The Discord bot was disconnecting during CSV processing with errors:
```
WARNING - Shard ID None heartbeat blocked for more than 20 seconds.
ClientConnectionResetError: Cannot write to closing transport
```

Additionally, transactions were categorized but never uploaded to Google Sheets (stuck in session file).

## Root Cause

Synchronous `subprocess.run()` calls in Claude CLI integration were blocking the Discord bot's event loop:

- Each AI categorization call took 7-10 seconds
- With 19 transactions, the bot was frozen for 2-3 minutes
- Discord requires heartbeats every ~40 seconds, so bot disconnected
- Session never completed, so transactions were never uploaded

**Blocking locations:**
1. `src/automation/claude_provider.py:120` - `subprocess.run()` in `_complete_cli()`
2. `src/automation/claude_provider.py:180` - Synchronous Anthropic API calls

## Solution

Converted entire AI categorization pipeline to async/await:

### 1. Claude Provider - Core Async Conversion

**File**: `src/automation/claude_provider.py`

**Changes:**
- ✅ Imported `AsyncAnthropic` instead of `Anthropic`
- ✅ Changed `complete()` to `async def complete()`
- ✅ Converted `_complete_cli()` to use `asyncio.create_subprocess_exec()`
- ✅ Converted `_complete_api()` to use async Anthropic client
- ✅ Added proper timeout handling with `asyncio.wait_for()`

**Before (blocking):**
```python
def _complete_cli(self, prompt: str) -> str:
    result = subprocess.run(
        cmd,
        capture_output=True,
        text=True,
        timeout=180
    )
    # Blocks entire event loop for 7-10 seconds
```

**After (non-blocking):**
```python
async def _complete_cli(self, prompt: str) -> str:
    process = await asyncio.create_subprocess_exec(
        *cmd,
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.PIPE
    )
    stdout, stderr = await asyncio.wait_for(
        process.communicate(),
        timeout=180
    )
    # Allows Discord heartbeats to run
```

## Technical Details

### Why Async?

Discord.py uses `asyncio` for all network I/O. When a synchronous blocking call happens:

1. Event loop is paused
2. No network activity can happen
3. Discord gateway requires heartbeats every ~40 seconds
4. After 20+ seconds of blocking, Discord logs heartbeat warning
5. After ~40 seconds, connection dies

**Synchronous call timing:**
- 1 transaction: ~7 seconds (blocked)
- 10 transactions: ~70 seconds (❌ disconnects)
- 19 transactions: ~133 seconds (❌❌ guaranteed disconnect)

**Async call timing:**
- 1 transaction: ~7 seconds (but event loop can process heartbeats)
- 10 transactions: ~70 seconds (✅ stays connected)
- 19 transactions: ~133 seconds (✅ stays connected)

### Async Subprocess Benefits

Using `asyncio.create_subprocess_exec()` instead of `subprocess.run()`:

| Feature | `subprocess.run()` | `asyncio.create_subprocess_exec()` |
|---------|--------------------|------------------------------------|
| Blocks event loop | ❌ Yes | ✅ No |
| Can process heartbeats | ❌ No | ✅ Yes |
| Discord bot compatible | ❌ No | ✅ Yes |
| Performance | Same | Same |
| Code complexity | Simple | Slightly more complex |
